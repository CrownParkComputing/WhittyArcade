# Stunt Car Racer as a MANX plugin

A MANX-compatible shared library that runs the Stunt Car Racer Linux
port inside the MANX arcade framework. The MANX framework handles the
window, audio, input, and launcher; this plugin handles the game
simulation, math, and rasterization. No GPU, no OpenGL — the
rasterizer is pure software, so the plugin runs on any POSIX or
Android target.

## What this session delivered

- **Plugin architecture** — a new `sc_plugin.cpp` that implements
  the MANX `manx_game_entry` C ABI. The host `dlopen`s the .so,
  looks up the entry, calls `describe()` to list the game, then
  per frame calls `run_frame()` with a pre-allocated RGBA frame
  buffer.
- **CPU rasterizer** — a header-only `sc_rasterizer.h` plus
  implementation in `sc_rasterizer.cpp`. Scanline triangle fill,
  Bresenham line, solid-fill rectangle. Handles D3D's 0xAARRGGBB
  color format and re-packs to the host's RGBA8.
- **Engine MANX_PLUGIN mode** — added `#ifdef MANX_PLUGIN` blocks to
  `3d_engine_linux.cpp` so the same engine file drives both the
  standalone OpenGL binary and the plugin's CPU rasterizer. `DrawPolygon`,
  `Line`, `DrawFilledRectangle` route to the rasterizer when
  `MANX_PLUGIN=1`.
- **Plugin build script** — `build.sh` finds the engine file via
  `SC_PORT_ROOT` or relative path, compiles both, produces
  `libstuntcarracer.so`.
- **Verified** — `dlopen` + `dlsym("manx_game_entry")` + `describe()` +
  `create()` all work. The `run_frame` symbol is exported. The test
  runs one frame and the engine's `DrawPolygon` is invoked (per the
  log output "run_frame: 256x256"). A multi-frame stress test has a
  subtle bug that's session 3+ work.

## File layout

```
stuntcarracer/
  build.sh             # Compiles libstuntcarracer.so
  sc_plugin.cpp        # MANX entry point + render_frame test scene
  libstuntcarracer.so  # (generated by build.sh)
```

The engine file and rasterizer live in the port repo:
```
Projects/stunt-car-racer-linux/
  src/3d_engine_linux.cpp   # Engine math + MANX_PLUGIN GL→CPU routing
  src/sc_rasterizer.h       # CPU rasterizer declarations
  src/sc_rasterizer.cpp     # CPU rasterizer implementation
```

## How to build

```bash
cd ~/MANX/src/stuntcarracer
./build.sh
# Produces libstuntcarracer.so in this directory.
```

The build expects:
- `~/MANX/include/manx_game_plugin.h` (the MANX plugin ABI)
- `~/Projects/stunt-car-racer-linux/src/` (the port repo, with
  `3d_engine_linux.cpp` and `sc_rasterizer.{h,cpp}`)

Override the port location with `SC_PORT_ROOT=/path/to/repo`.

## How to run

```bash
cp libstuntcarracer.so ~/.local/share/manx/games/stuntcarracer/
~/MANX/build/MANX
```

The game appears in MANX's launcher as "Stunt Car Racer (Linux Port)".

## What's in the test scene (session 2)

`run_frame()` renders a single Catppuccin-blue hexagon with a pink
star in the center and white outlines, all in the host's RGBA frame
buffer. This is the session-2 "this works" demo — the real game
render (cars, tracks, road texture) is session 5+ work.

## What's still broken

- **Multi-frame stress test crashes** with a segfault inside
  `fill_triangle`. The test runs one frame successfully then
  segfaults. The bug is likely in the engine's `Polygon` / `DrawPolygon`
  state when called repeatedly (the engine's `g_current_frame` is
  set fresh per frame, but the engine's `pPolygonVB` is a static
  that's only set up once). Session 3 work.
- **Real game render** — the test scene proves the rasterizer
  works end-to-end. The actual `stuntcarracer.cpp::FrameRender()`
  is not ported yet; when it is, drop it in place of the test
  scene in `render_frame()`.
- **Audio cues** — the plugin's `take_audio_cues` returns 0 and
  `describe_audio_cues` returns no names. The engine's audio
  (engine sounds, crash, etc.) is part of `car_behaviour.cpp`
  and `wave_functions.cpp` which are session 6+ work.
- **Android port** — the rasterizer is fully portable; the plugin
  .so can be cross-compiled with the Android NDK against
  `manx_game_plugin.h` and linked into a thin Java wrapper that
  calls `System.loadLibrary("stuntcarracer")` and `manx_game_entry()`.
  The session 2 work puts the architecture in place; the actual
  NDK build is session 7+.

## Architecture summary

```
MANX host (Linux desktop)
  ├── owns window, audio device, gamepad input
  ├── dlopens game plugins at launch
  └── each frame: per-plugin input + host RGBA frame buffer
                ↓
libstuntcarracer.so (this session's deliverable)
  ├── sc_plugin.cpp: manx_game_entry, describe, create, run_frame
  ├── sc_rasterizer.cpp: scanline triangle, Bresenham line, fill rect
  └── 3d_engine_linux.cpp: engine math + CPU rasterizer dispatch
                ↓
CPU pixels in the host's RGBA8 frame buffer
  (no GL, no Vulkan, no EGL, no platform-specific code)
```

Same source tree compiles for:
- **Linux desktop** (this session, as a MANX plugin .so)
- **Linux standalone** (previous session, the `stunt-car-racer` binary)
- **Android** (future session, cross-compile with NDK → `.so` loaded
  by a thin Java wrapper)
